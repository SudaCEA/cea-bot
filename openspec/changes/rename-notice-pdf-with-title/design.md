# Design: rename-notice-pdf-with-title

## Context

- 产物名由纯函数 `pdf_file_name(published_on, edit_id)` 生成（`src/cea_bot/notices/pdf.py`），
  规则是 `_UNSAFE.sub("", ...)` 拼接 —— 而 `_UNSAFE = [^0-9A-Za-z._-]+` 是**ASCII 白名单**，
  会把标题里的中文**整段删空**。所以"文件名带标题"必须连净化策略一起换，不是改一行 f-string。
- 调用点只有一处：`handlers/notice.py` 的 `_push_one`，它同时持有 `row.title`
  （`NoticeRow` 已含标题，无需额外查询）。
- 该产物渲染后**立即发送**，同时作为归档留在 `notice_pdf_dir`。

## Goals / Non-Goals

**Goals:**

- 归档目录里一眼可读：`261001-通知标题.pdf`
- 中文标题完整保留；文件系统非法字符不落到文件名里
- 重名时不静默覆盖

**Non-Goals:**

- 不迁移/重命名历史产物
- 不改 PDF 内容与渲染参数（A4、页边距、中文字体一律不动）
- 不在文件名里保留 `editId`（用户明确要求的格式里没有它）→ 代价见 D4

## Decisions

**D1. 格式 `YYMMDD-<标题>.pdf`。**
`published_on` 为 ISO `YYYY-MM-DD`，取"年后两位 + 月 + 日"。例：`2026-10-01` + `通知标题`
→ `261001-通知标题.pdf`。

**D2. 净化改为黑名单（剔除非法字符），而不是继续用 ASCII 白名单。**
非法集合：`< > : " / \ | ? *`、控制字符（`\x00-\x1f`）、以及路径分隔符；
并额外剔除标题**结尾**的 `.` 与空格 —— Windows 会静默丢弃它们，导致"库里记的名字"与
"磁盘上的名字"不一致，那正是本仓库最忌讳的静默失效。
备选：继续白名单 + 中文转拼音 —— 引入依赖且更难读，否。

**D3. 标题截断到 80 个字符；日期非 ISO 或缺省用 `000000`；标题净化后为空用 `未命名`。**
80 字符的由来：Windows MAX_PATH 为 260；`notice_pdf_dir` 是绝对路径（本项目默认约 44 字符），
再加 `YYMMDD-`(7) 与 `.pdf`(4)，仍有充足余量；校园通知标题通常远短于 80。
用固定占位而不是留空：留空会生成 `261001-.pdf` 这类难辨认的名字。

**D4. 同名（同日同标题）时记 WARNING 后覆盖，不静默覆盖；不加自动后缀。**
`pdf_file_name` 保持**纯函数**（同输入必得同输出，可离线单测）；重名检测放在调用点
（那里才有文件系统与连接）：渲染前若目标文件已存在，记 WARNING（含 `edit_id` 与路径）。
备选：自动追加 `-<editId>` 消歧 —— 但那会让文件名格式在边界情况不一致，且需要在纯函数之外
做 DB 查询才能定名。**已知代价**：同日同标题的两条通知，后者的 PDF 会覆盖前者，
状态库里两条记录的 `pdf_path` 指向同一文件。若日后需要消歧，加后缀属新的行为变更。

**D5. 不迁移历史产物。**
归档里已有的 `2026-10-13-40775683.pdf` 等保持原样；状态库旧的 `pdf_path` 不回填。
理由：迁移要动运行数据，而收益只是命名统一；旧文件早已发送过，其价值仅是留档。

**D6. 日期只校验形式（`YYYY-MM-DD`），不校验日历真实性** —— `2026-13-45` 照转成 `261345`。
理由有二：① 解析层只会产出 `_DATE` 命中的形式，这里再叠一层日历校验只会多一条无人依赖的失败分支；
② 更重要的是**信息可见性** —— 站点真给出 `2026-13-45` 时，照转能让这个异常**留在文件名里一眼可见**，
换成 `000000` 反而把"是哪一条、异常在哪"藏起来，那才是静默失效。
安全性不受影响：名字恒以 `YYMMDD-`（或 `000000-`）开头，构造不出 `.`、`..` 或空名。

## Risks / Trade-offs

- [同日同标题撞名导致覆盖] → D4 记 WARNING；需要消歧可后续加后缀（新的变更）
- [校园通知标题里 `/` 很常见（如"关于XX/YY的通知"）] → D2 黑名单剔除，并有用例覆盖
- [超长标题触发 MAX_PATH 导致渲染失败] → D3 截断；渲染失败本就有"降级为只发文本并记告警"的既有分支
- [目录里新旧两种命名风格并存] → D5 明确不迁移，并在 README 写明
