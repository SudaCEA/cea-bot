# Design

## Context

动机见 `proposal.md`。这里只列影响做法的现状约束：

- **解析层是纯的**：`src/cea_bot/notices/parse.py` 目前只 import `codecs` / `re` / `html.unescape`
  与 `.models`，**没有 logger**，也不碰文件系统与网络。日期取自 `_brief_of_row`（行内按位置取单元格，
  取不到再整行扫一遍，见 `parse.py:267-277`）。
- **`published_on` 被四处消费**：排序（`schema.pending` 的 `ORDER BY published_on DESC`）、
  PDF 命名（`pdf._date_stamp`）、推送文本与摘要的元信息行（`handlers/notice.py:156`、
  `summarize.py:76`）。**没有任何一处做二次规范化** —— 谁产出什么，就一直是什么。
- **`_ISO_DATE` 已经是 ASCII 口径**：`pdf.py:52` 只认 `[0-9]`，且有既有用例钉住
  "非 ASCII 数字 → `000000`"（`tests/test_notice_pdf.py:176`）。也就是说**命名层早已按"日期必然是
  ASCII"假设在工作**，只有解析层没跟上 —— 这次是把解析层拉到同一个假设上，而不是去改命名层。
- **既有告警口径**：`handlers/notice.py:259` 对"缺少发布日期"是**聚合**告警（`N/M 条 …`），
  不是逐条刷屏；新告警要与它口径一致。
- **实测事实**（`.local/probe_date_forms.py`，2026-10-18）：三个栏目首页共 60 条，发布日期全是 ASCII，
  整页非 ASCII `Nd` 字符数为 0。**本次没有任何现场样本可依赖**，正确性只能靠单测构造输入。

## Goals / Non-Goals

**Goals:**

- 解析层对外**只产出 ASCII `YYYY-MM-DD`**，让排序、命名、展示三处共享同一个假设；
- 归一化**可见**：发生了几次就记几次的聚合日志，且**不逐条刷屏**；
- 归一化**不引入新的中止路径**：认不出来的日期退回"发布日期缺失"，绝不因此让整轮中止。

**Non-Goals:**

- 不放宽"什么算日期"：未补零（`2026-1-3`）、中文数字（`二〇二六年十月一日`）继续算缺失；
- 不动匹配边界（`\d{4}` 仍可能在更长的数字串中间命中，见 D3）；
- 不改 PDF 命名层、不改状态库、不改任何配置键；
- 不迁移库里已有的非 ASCII 日期行。

## Decisions

### D1 接受集合：数字沿用 `\d`（Nd），连字符**新增**全角 `－`（U+FF0D）

`_DATE` 由 `\d{4}-\d{2}-\d{2}` 变为 `\d{4}[-\uFF0D]\d{2}[-\uFF0D]\d{2}`。

- **数字侧不缩不放**：Python 在 `str` 模式下 `\d` 恰好就是 Unicode `Nd` 类，今天已经在认全角数字了。
  把它缩成 `[0-9０-９]` 会**新增一个拒绝分支**（页面上出现阿拉伯-印度数字就变成"缺少日期"），
  与"把已有输入规范化"的目标相反。
- **连字符必须一起接**：中文输入法全角状态下打出的日期是 `２０２６－１０－０１`，
  数字和连字符**同时**是全角。只归一化数字的话，这个字符串根本不会被 `_DATE` 命中，
  于是本次要修的场景照旧落成"缺少日期" —— 修了等于没修。
- **只加 `－`，不加 `‐`/`–`/`—`/`−`**：那些来自正文排版（实测 fixtures 里的 `——` 全在标题里），
  不是"输入日期"的形态；放宽它们会让正文片段有机会被当成日期。

**考虑过的替代方案 —— `unicodedata.normalize("NFKC", …)`**：一行就能把全角数字与全角连字符都变成
ASCII，代码更少。**拒绝**：NFKC 会**放宽接受集合**，把 `②`、`²` 这类非 `Nd` 字符也变成数字，
于是"什么算日期"被悄悄改了 —— 那是规格之外的行为变化。本次要的是"接受集合不变、
把它的产物规范化"，所以用逐字符取十进制值的显式映射。

### D2 归一化在**入口做一次**，产物即规范形式

在 `_brief_of_row` 拿到日期串后立刻归一化，`published_on` 落库/进模型时**已经是** ASCII。

- **替代方案**：在读取（`schema.pending` 写 SQL `REPLACE`）、展示（文本/摘要拼装）、命名
  （`_date_stamp`）各做一次。**拒绝**：四个消费点就得各记一条规则，漏一个就是新的口径不一致；
  而且排序用的是 SQL 比较，靠读取层修正会连索引一起绕过。
- **实现用 `int()` 而不是手工查表**：CPython 的 `int()` 认**全部** `Nd` 数字（Unicode 十进制值），
  于是 `f"{int(a):04d}-{int(b):02d}-{int(c):02d}"` 同时给出"数字归一化"与"定宽补零"两个保证，
  连 `unicodedata` 都不必 import。

### D3 匹配边界不动，并把它记为**既有**缺陷

`_DATE` 用的是 `search` 且没有左右边界，所以 `12345-67-89` 会命中 `2345-67-89`。
这是本次之前就有的行为，**不顺手修**：改边界会把这次变更从"日期口径"扩到"日期识别规则"，
而它同样没有触发证据。做法是：在 `_DATE` 旁的注释里写明这个已知边界，
`dev-docs/backlog.md` 另立一条待办（本次不处理）。

### D4 告警在解析层**聚合一条** WARNING，不给 `NoticeBrief` 加字段

- 归一化是**解析步骤**的属性，不是"一条通知"的属性。为它给领域模型加 `date_normalized` 之类的字段，
  会让 `NoticeBrief` 的语义从"页面上的通知"变成"解析过程的副产物容器"。
- 因此 `_brief_of_row` 内部返回 `(brief, normalized: bool)`，由 `parse_list` 聚合后记一条
  `列表页有 N/M 条日期被归一化为 ASCII（页面给出非 ASCII 数字或全角连字符）`。
  两个函数都是模块私有，**公开签名不变**（`parse_list` 仍返回 `list[NoticeBrief]`）。
- **级别取 WARNING**：`DEBUG` 在默认日志配置下等于没记，与规格"SHALL 记录日志"相悖；
  文案与既有的"缺少发布日期"告警**用词不同**，两条可以同时出现、互不冒充。
- `parse.py` 因此新增 `logging` 与 `log = logging.getLogger("cea")`（与全仓库同一个 logger 通道）。

### D5 不写迁移代码

库里若存在老版本写入的非 ASCII 日期行，它们仍会排在队首。**不为它写迁移**：真实数据里 0 条
（60 条实测 + 状态库已重建），而这类行的正确处置与既有 `STATE_REMEDY` 一致 —— 备份后删库重建基线。
代价是"某个部署若真有这类行，得自己发现"；缓解方式是在 README 的"重置状态"处补一句
（见 tasks 4.1），把处置写在使用者能看到的地方，而不是埋一段永不触发的代码。

### D6 "最近优先"这条规格场景要用**真实投递顺序**验证

规格新增的场景问的是"旧条目会不会因为日期写法插到队首"，所以它必须走真实的
`parse → 登记 → pending → 投递` 路径（handler 层，配假依赖）来断言顺序，
**不接受**"自己比较两个字符串谁大"这种把被测行为换掉的写法。

## Risks / Trade-offs

- **[行为变化：原本算"缺失日期"的全角条目现在有日期了]** → 这正是规格变更本身；
  已核对既有用例：`tests/test_notice_pdf.py:176` 只针对 `pdf_file_name` **单函数**，不经过解析层，
  故不受影响。tasks 里要求实施后再 grep 一次"非 ASCII → 缺失"类断言。
- **[归一化把异常吞掉、变成静默降级]** → `_normalize_date` 认不出来时返回 `None`，
  该条按"缺少发布日期"处理，落进既有聚合告警；且该分支由单测**直接喂非 `Nd` 串**触发，
  不是靠"理论上不会发生"糊过去。
- **[聚合告警被误读成"页面改版"]** → 两条告警文案刻意区分（"缺少发布日期" vs "日期被归一化"），
  并各有单测钉住措辞。
- **[归一化后与 HTML 页面上看到的不一致，事后核对困难]** → 日志里给出条数；本次不存原文
  （存原文等于给状态库加列，收益低于成本），若将来要溯源再另立变更。

## Migration Plan

- **部署**：无状态迁移，随代码生效；旧版本写入的 ASCII 日期不受影响。
- **回滚**：直接回退代码。归一化后的值本身就是 ASCII `YYYY-MM-DD`，旧版本读它没有任何问题
  （回滚不会让数据变得不可读）。
